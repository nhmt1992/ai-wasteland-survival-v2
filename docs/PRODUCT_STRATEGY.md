# Product Strategy v2

## 1. 产品定位

AI Wasteland Survival v2 先做的是一个能上线的 AI-NPC 生存直播闭环。

首发不是多主播 SaaS，也不是只给单个主播做演示页，而是先把一个主播的直播玩法跑通：

```text
服务端维护世界状态。
主播用 game-client 直播和收礼物反馈。
观众创建 AI-NPC 并观看自己的 NPC。
礼物通过标准化事件进入世界。
```

## 2. 核心客户

直接客户仍然是主播，但首发阶段只服务一个主播闭环，先验证能不能上线、能不能留人、能不能产生礼物互动。

| 客户 | 需求 |
|---|---|
| TikTok 主播 | 有一个能播的世界和稳定的礼物反馈 |
| 观众 | 创建自己的 NPC，并继续看自己的 NPC |
| 平台运营者 | 先把可复用的核心服务做稳，后续再扩展成 SaaS |

## 3. 核心价值

对主播：

```text
低成本获得一个可以直接开播的 AI 沙盒世界。
礼物支援能直接影响直播画面。
主播可以围绕 NPC 生死和危机讲故事。
```

对观众：

```text
自己的 TikTok ID 绑定一个 AI-NPC。
NPC 会在主播世界里自主生存。
礼物能支援自己的 NPC，但不能直接控制。
NPC 会产生记忆、关系、死亡和遗产。
```

对平台：

```text
先验证一个闭环能不能上线。
服务端、game-client、viewer 三端先跑通。
未来再把这一套抽象成多主播 SaaS。
```

## 4. 商业模式

### 4.1 首发阶段

```text
先验证可上线闭环，不先做完整计费和套餐。
```

### 4.2 后续方向

```text
主播月费订阅
更多 NPC 容量
更多世界数量
自定义直播外观
主播品牌 Logo
高级数据分析
AI 事件旁白额度
长期世界存档
活动模板
```

## 5. 游戏循环

```text
主播开播
→ 观众通过主播链接创建 NPC
→ NPC 进入主播专属世界
→ NPC 自主生存、结盟、争夺资源
→ 世界制造危机
→ 主播讲述危机
→ 观众刷礼物支援
→ 礼物通过主播直播间进入对应世界
→ NPC 获得资源但仍自主判断
→ 形成新的直播故事
```

## 6. 平台收益闭环

```text
游戏提高主播直播互动
→ 主播更容易持续开播
→ 观众愿意围绕自己的 NPC 互动
→ 礼物反馈更明确
→ 先证明这个闭环值得继续做
```

## 7. 产品边界

### 平台负责

```text
世界运行
NPC AI
礼物事件标准化
用户创建链接
用户观看端
数据存储
权限隔离
后续扩展的多租户上下文
```

### 主播负责

```text
自己的 TikTok 直播账号
直播内容表达
用 game-client 播放和讲述世界
引导观众创建 NPC
引导观众礼物支援
```

### 观众负责

```text
创建 NPC
观看 NPC
通过礼物支援 NPC
```

## 8. MVP 成功标准

```text
一个主播能启动 game-client 并进入自己的世界。
一个主播能看到礼物事件反馈。
观众能通过主播链接创建 NPC。
观众能查看自己的 NPC。
模拟礼物能进入该主播世界。
5 个 NPC 能运行 1 小时。
主播能围绕 NPC 事件讲故事。
```

## 9. 暂不做

```text
多主播正式注册。
所有主播共享大世界。
复杂分账。
真实 TikTok 官方深度接入。
公会多账号权限。
完整数据分析系统。
移动 App。
```
