# game-client 中文使用说明书

`game-client` 是主播窗口里的 2.5D 游戏画面客户端，用来在直播时展示荒土世界、NPC、礼物演出和危险状态。

它不是主播后台，也不是观众端。它只负责读取世界快照并渲染画面。

## 1. 使用前提

开始前先确认：

- 后端已经启动。
- `game-client` 已经启动。
- 你知道当前主播的 `streamerHandle` 和 `worldId`。
- 浏览器或 OBS 可以访问本机端口 `5177`。

## 2. 启动方式

先启动后端：

```bash
npm run dev:backend
```

再启动 `game-client`：

```bash
npm run dev:game
```

默认地址是：

```text
http://localhost:5177
```

## 3. 打开画面

`game-client` 的路由格式是：

```text
/game/:streamerHandle/:worldId
```

示例：

```text
http://localhost:5177/game/matt/00000000-0000-0000-0000-000000000101?mode=live
```

如果要看压力测试画面：

```text
http://localhost:5177/game/matt/00000000-0000-0000-0000-000000000101?mode=stress&npcCount=1000&debug=1
```

## 4. 参数说明

### `mode`

- `live`：读取后端真实快照和实时事件。
- `stress`：使用本地合成世界，方便做画面和性能测试。

### `npcCount`

- 只在 `stress` 模式下生效。
- 取值范围是 `1` 到 `1000`。
- 默认是 `1000`。

### `debug`

- `debug=1` 或 `debug=true` 会显示调试信息。
- 正式直播建议关闭。

## 5. 画面操作

- 拖拽画面：平移镜头。
- 滚轮：放大或缩小镜头。
- 镜头会自动跟随当前重点 NPC。

## 6. 画面内容

你会在画面里看到这些内容：

- 荒土等距地表
- 背景尘雾和地平线
- NPC 角色
- 植被、废墟、动物、野兽
- 资源箱和礼物演出
- 名字牌和状态条
- 底部 HUD

## 7. 两种模式怎么用

### live 模式

适合正式演示和联调。

特点：

- 读取后端 snapshot。
- 监听 realtime WebSocket。
- 礼物、Tick、危机状态会同步刷新。

适用场景：

- 主播直播
- 接后端真实数据验证
- 联调礼物和世界状态

### stress 模式

适合测试和截图验收。

特点：

- 本地生成 1000 NPC。
- 本地生成地图、资源、动物、野兽和事件样例。
- 不依赖后端扩容。

适用场景：

- 性能测试
- 镜头和 HUD 调整
- 画面风格验证

## 8. OBS 采集建议

- 使用 OBS 的 Window Capture 采集 `game-client` 窗口。
- 建议窗口分辨率保持在 `1920 x 1080` 或直播常用采集分辨率。
- `debug=1` 只用于开发和验收，正式直播建议关闭。
- 如果主播需要操作镜头，可以保留鼠标输入；如果只想固定画面，可以不操作。

## 9. 构建方式

如果你只想生成生产包：

```bash
npm --workspace game-client run build
```

构建输出在：

```text
game-client/dist/
```

## 10. 常见问题

### 画面是空白的

先检查：

- 后端是否启动。
- `game-client` 是否在运行。
- URL 的 `streamerHandle` 和 `worldId` 是否正确。
- 浏览器控制台是否有报错。

### 画面没有 NPC

先检查：

- 当前是否打开了正确的 world。
- 是否误进了空世界或错误路由。
- 是否把镜头拖到了很远的位置。
- 是否把 `debug` 关掉后误以为是隐藏了实体。

### 采集卡顿

先尝试：

- 关闭其他重型程序。
- 用 `stress` 模式时把 `npcCount` 降一点。
- 确认不是浏览器扩展或系统录屏工具抢占性能。

### 礼物没显示

先检查：

- 是否是 `live` 模式。
- WebSocket 是否连上。
- 后端实时事件是否有推送。

## 11. 适合主播的最小操作流程

1. 启动后端。
2. 启动 `game-client`。
3. 打开 `live` 路由。
4. 用 OBS Window Capture 采集窗口。
5. 直播时只保留必要的镜头操作。

## 12. 备注

这个客户端的设计目标是：

- 远看像正式游戏。
- 直播时信息清楚。
- 1000 NPC 场景仍然可读。
- 只读后端数据，不写世界状态。

如果你要继续扩展，下一步通常是：

- 更细的 NPC 角色外观。
- 更强的礼物特效。
- 更完整的直播 HUD。
